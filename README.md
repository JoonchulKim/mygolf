# My Golf · 나의 골프 기록

아이폰에서 매 샷을 기록하고 라운드 후 실수를 복기하는 개인용 웹앱입니다. 설치할 패키지나 별도 서버 없이 HTML/CSS/JavaScript로 동작합니다.

## 아이폰에서 사용하기

1. HTTPS로 배포한 웹 주소를 Safari로 엽니다.
2. 공유 → **홈 화면에 추가**를 선택합니다.
3. 홈 화면의 **My Golf** 아이콘으로 실행합니다. 설정에서 **오프라인 기록 준비 완료**를 확인합니다.
4. **새 라운드 시작**에서 골프장·날짜·9/18홀을 입력합니다.
5. 홀별 Par를 지정하고 **클럽 → 1~5점 → 샷 저장** 순서로 기록합니다.
6. 실수·상황·벌타는 선택 입력입니다. 매 샷 입력해도 되고, 홀을 마친 뒤 연속으로 입력해도 됩니다.
7. **홀 마무리**에서 타수와 GIR을 확인합니다. 홀 번호나 스코어카드를 누르면 이전 홀도 수정할 수 있습니다.
8. 라운드 후 **분석**에서 클럽별 평가, 미스 유형, 다시 볼 홀, 전체 라운드별 추이를 확인합니다.
9. **설정과 백업 → 전체 기록 백업**에서 파일 앱 또는 iCloud Drive에 JSON 파일을 보관합니다.

### 기본 클럽과 평가

드라이버, 3U, 5I, 6I, 7I, 8I, 9I, P, 52°, 56°, 60°, 퍼터. 설정에서 목록을 변경할 수 있으며 과거 기록은 유지됩니다.

| 점수 | 의미 |
|---|---|
| 5 | 완전 잘 친 샷 |
| 4 | 그럭저럭 잘 친 샷 |
| 3 | So-so, 보통 |
| 2 | 의도한 대로 안 나온 샷 |
| 1 | 완전 망한 샷 |

평가를 건너뛴 샷은 **미평가**로 유지합니다. 클럽 선택만으로도 저장할 수 있습니다. 의도한 탈출을 성공했다면 높은 점수를 줘도 됩니다.

### 계산 원칙

- 총타수 = 실제로 친 샷 + 벌타 + 실제로 치지 않은 컨시드 타수.
- OB 재타격은 원래 샷에 벌타 +1을 붙이고, 다시 친 샷은 별도로 기록합니다.
- OB티 +2 버튼은 해당 진행 방식을 이용하는 경우에만 선택합니다. 모든 OB를 일괄 +2 처리하지 않습니다.
- 그린 밖에서 퍼터를 썼다면 **그린 위에서 친 퍼트**를 해제합니다.
- 컨시드는 타수에 포함하되 실제 샷 수, 퍼팅 수, 샷 평가에서 제외합니다.
- 샷 평가 비율은 미평가 포함 실제 샷 수가 분모입니다. 평균 점수에서는 미평가를 제외합니다.
- GIR은 자동 추정하지 않고 홀 마무리에서 직접 예/아니요/모르겠음으로 입력합니다.
- 샷·순서·Par를 수정하면 해당 홀 완료 및 GIR 확인을 해제합니다. 다시 홀 마무리를 해 주세요.
- 스코어카드 합계의 Par는 기록된 홀 기준입니다. 모든 홀의 기본 Par는 4이므로 실제 코스에 맞게 변경해야 합니다.

### 수정 및 몰아 입력

샷 목록의 **여기에 샷 추가**로 중간 삽입, **수정**으로 변경, ↑↓로 순서 이동이 가능합니다. 삭제 후 잠시 표시되는 **되돌리기**로 직전 변경을 취소할 수 있습니다. 저장 전 입력도 같은 기기에서 다시 열 수 있도록 임시 보관합니다. 다른 홀로 이동할 때 미저장 입력을 버릴지 확인합니다.

## 데이터 보관과 개인정보

- 기록은 브라우저의 **IndexedDB**, 입력 중 초안은 localStorage에 보관합니다. 서버 전송, 분석 추적, 외부 CDN, GitHub 토큰이 없습니다.
- 앱 코드와 개인 골프 기록은 분리됩니다. GitHub 저장소에는 개인 기록을 커밋하지 마세요.
- 계정·클라우드 동기화가 없는 **기기 전용** 앱입니다. 다른 기기나 브라우저, 다른 배포 주소는 별도 저장소를 사용합니다.
- Safari와 홈 화면 앱의 데이터가 다를 경우 백업·복원으로 옮기고, 이후 같은 아이콘으로 사용하세요.
- 브라우저 데이터 삭제, 기기 분실·교체, 저장 공간 정리 등으로 로컬 기록이 없어질 수 있습니다. 정기적으로 백업하세요.
- 백업은 실제 파일 저장까지 완료해야 안전합니다. ‘최근 백업 내보내기’ 시각은 파일의 보관 여부를 보장하지 않습니다.
- 복원은 형식을 검증한 뒤 확인을 받아 현재 전체 기록을 교체합니다. 이전 기록은 먼저 백업하세요. 지원 백업은 v1 JSON, 10MB 이하입니다.
- 두 화면의 동시 편집은 revision 검사로 덮어쓰기를 방지합니다. 충돌 안내가 나오면 새로고침 후 다시 입력하세요.
- 사이트에 로그인 제한을 넣지는 않았습니다. 다른 사람이 같은 웹 주소에 접속해도 이 기기의 기록은 서버에서 조회되지 않습니다. 기기를 직접 사용하는 사람은 기록을 볼 수 있습니다.

## 실행 및 배포

### 로컬 개발

```sh
python3 -m http.server 8000
# http://localhost:8000
node --test tests/core.test.js
```

`file://`로 HTML을 직접 여는 방식은 지원하지 않습니다. 서비스 워커는 HTTPS 또는 localhost가 필요합니다. 외부 패키지 설치와 빌드 과정은 필요 없습니다.

### GitHub Pages

현재 저장소를 비공개로 유지한 채 배포하려면 해당 계정에 비공개 저장소의 Pages를 사용할 수 있는 요금제가 필요합니다. **비공개 저장소와 비공개 웹사이트는 별개**이며, 일반 Pages 사이트는 공개될 수 있습니다. 저장소의 공개 범위를 자동으로 변경하지 않습니다.

가장 간단한 방법:

1. 저장소 **Settings → Pages → Build and deployment**로 이동합니다.
2. Source를 **Deploy from a branch**, Branch를 **main**, 폴더를 **/(root)**로 지정하고 Save 합니다.
3. Pages 화면에 실제 배포 완료 주소가 표시되면 Safari에서 엽니다.
4. 첫 방문 때 인터넷에 연결한 상태로 설정의 오프라인 준비 완료를 확인합니다.

주소는 일반적으로 `https://joonchulkim.github.io/mygolf/` 형식입니다. Pages 설정·배포가 완료되기 전에는 이 주소가 동작하지 않습니다. Pages를 사용할 수 없는 요금제라면 비공개 저장소를 지원하는 별도 정적 호스팅을 선택하세요. 앱은 어느 HTTPS 정적 호스팅에서도 빌드 없이 실행할 수 있습니다.

### 앱 업데이트

`sw.js`의 `CACHE` 버전을 매 배포마다 올리세요. 새 버전은 캐시에 준비되고 기존 화면을 모두 닫았다 다시 열면 적용됩니다. 기록 DB는 캐시와 분리되어 업데이트해도 유지됩니다. 임의의 서비스 워커 캐시나 사용자 DB를 일괄 삭제하지 않습니다.

## 구성

- `index.html`, `style.css`, `app.js`: 아이폰 우선 UI와 입력 흐름
- `core.js`: 타수·통계 계산, 백업 검증
- `storage.js`: IndexedDB 영속 저장과 동시 편집 검사
- `sw.js`, `manifest.webmanifest`, `icons/`: 설치·오프라인 앱
- `tests/core.test.js`: 벌타·컨시드·미평가·퍼팅·백업 검증 테스트

코스 자동 검색, GPS 거리 측정, 클라우드 동기화, 자동 스윙 감지는 포함하지 않습니다. 입력한 데이터의 범위 안에서 복기합니다.
